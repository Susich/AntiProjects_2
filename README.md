# PartySplit — делим счёт честно (Split Bill & Debt Simplification) 🍹🧾

Мобильное приложение на **React Native (Expo) + TypeScript** для совместного ведения чека, сведения долгов и синхронизации оплат между устройствами. Пользователи регистрируются, входят в общие комнаты по коду и отмечают переводы; приложение показывает банк и телефон получателя, но **не создаёт платёжные ссылки и deep links**.

---

## 🔐 Авторизация и личный профиль

При первом запуске открывается полноэкранный экран входа:

- **Регистрация:** имя, телефон, банк по умолчанию и пароль.
- **Вход:** телефон + пароль.
- Сессия сохраняется в `AsyncStorage`; при следующем запуске приложение не просит пароль повторно.
- Пароли на сервере хранятся как **соль + SHA-256 хеш**, сессия подтверждается токеном.

Личный профиль (`ProfileScreen`) позволяет:

- просматривать и редактировать имя, телефон и банк;
- видеть статистику за всё время: сколько потрачено на себя, сколько счетов оплачено и на какую сумму;
- открывать список оплаченных счетов с названием тусовки и датой;
- менять тему, настраивать Google Sheets и выходить из аккаунта.

Банк — это **только метка для отображения**. Приложение не строит ссылки на банковские приложения и не открывает внешние платёжные страницы.

## 🚀 Архитектура данных

### Пользователь (`UserProfile`)

```typescript
export interface UserProfile {
  id: string;
  name: string;
  phone: string; // +7XXXXXXXXXX
  bank: string;  // Сбербанк, Т-Банк, ...
  avatarColor?: string;
}
```

Глобальной «базы профилей» или списка сохранённых друзей больше нет. Участники комнаты — это авторизованные пользователи, которые присоединились к ней.

### Расход (`ExpenseItem`)

```typescript
export interface ExpenseItem {
  id: string;
  title: string;
  amount: number;
  paidById: string; // кто заплатил из своего кармана
  splitBetween: { userId: string; share?: number }[];
  category?: ItemCategory;
  date?: string;
}
```

### Комната (`PartyEvent`)

```typescript
export interface PartyEvent {
  id: string;
  code?: string; // код облачной комнаты, например PUB777
  title: string;
  date: string;
  participants: UserProfile[]; // авторизованные участники комнаты
  expenses: ExpenseItem[];
  settledTransferIds?: string[]; // оплаченные переводы, синхронизированные из таблицы
}
```

### Статус перевода (`TransferStatus`)

```typescript
export interface TransferStatus {
  transferId: string;
  fromUserId: string;
  toUserId: string;
  amount: number;
  isPaid: boolean;
  updatedAt?: string;
}
```

## ⚡️ Алгоритм расчёта и взаимозачёта

Реализован в `src/utils/debtSimplification.ts`:

1. Для каждого участника считается чистый баланс:
   `Net = сумма оплаченных им счетов − сумма его доли потребления`.
2. Участники делятся на кредиторов (`Net > 0`) и должников (`Net < 0`).
3. Жадный алгоритм сводит переводы напрямую «должник → кредитор», минимизируя их количество (не более `N − 1`).
4. Все суммы считаются в целых копейках, чтобы не накапливать ошибку округления.
5. Идентификаторы переводов детерминированы (`transfer_<from>_<to>`), поэтому отметка «Оплачено» остаётся связанной с нужным переводом при пересчёте.

## 📱 Экраны

### 1. «Чек & Траты» (`PartyScreen`)

- Список участников — авторизованные пользователи комнаты. Своего добавлять вручную не нужно.
- При создании или входе в комнату приложение просит **подтвердить банк для этого сбора**; по умолчанию подставляется банк из профиля.
- Участники подключаются по коду комнаты, а не через локальную базу друзей.
- Добавление расхода: кто оплатил, кто участвовал, категория, сумма. Есть переключатель «Скинулись все».
- Список счетов с плательщиком, категорией, участниками и действиями редактирования/удаления.
- Pull-to-refresh и автоматическое обновление комнаты.

### 2. «Итоги & Оплата» (`ResultsScreen`)

- Сводный баннер: общая сумма, количество переводов, прогресс оплаты.
- Раскрывающийся блок чистых балансов.
- **Статусы участников:** кто уже оплатил, кто ждёт перевода, кто в расчёте.
- Карточки переводов (`DebtorCard`):
  - должник, получатель, сумма;
  - **банк получателя** и **телефон**;
  - кнопка **«Скопировать номер»** с мгновенным подтверждением **«Скопировано!»**;
  - отметка «Оплачено» / «Вернуть в ожидание»;
  - кнопка «Поделиться» формирует текст без ссылок.
- Кнопка сохранения тусовки в архив.

### 3. «Профиль» (`ProfileScreen`)

- Личные данные, банк по умолчанию, редактирование профиля и пароля.
- Статистика за всё время и список оплаченных счетов.
- Настройки темы, Google Sheets и выход из аккаунта.

### 4. «Архив» (`HistoryScreen`)

- Сохранённые тусовки с итоговой суммой, количеством участников и позиций.
- Удаление записей. Загрузка архивной комнаты обратно в редактор больше не используется: новый сбор всегда формируется из авторизованных участников.

### 5. Темы оформления

- **Midnight Bar**, **Cyberpunk Neon**, **Craft Minimal**, **Clean Light**.
- Переключение в профиле или через иконку палитры в Header.

## ☁️ Google Sheets + Google Apps Script

Файлы:

- `backend/Code.gs` — Web App для Google Таблиц.
- `backend/DEPLOYMENT_GUIDE.md` — пошаговое развёртывание.
- `src/api/googleSheets.ts` — клиентский API, кэш чтения и очередь записи.
- `src/api/cloudQueue.ts` — последовательная очередь, батчи, retry/backoff и коалесинг запросов.
- `src/api/partyCache.ts` — in-memory + AsyncStorage кэш снимков комнаты.
- `src/hooks/useCloudAutoSync.ts` — SWR-опрос с адаптивным интервалом и паузой в фоне.
- `src/utils/cloudSync.ts` — слияние облачной комнаты с локальным состоянием.
- `src/utils/toastBus.ts` — тосты для фоновых ошибок очереди.

### Листы таблицы

| Лист | Колонки |
| --- | --- |
| `Users` | `id`, `name`, `phone`, `bank`, `legacyPaymentUrl`, `updatedAt`, `passwordHash`, `passwordSalt`, `sessionToken`, `createdAt` |
| `Parties` | `id`, `code`, `title`, `createdBy`, `createdAt` |
| `PartyMembers` | `partyId`, `userId`, `joinedAt`, `bank` |
| `Expenses` | `id`, `partyId`, `title`, `amount`, `paidById`, `sharedUserIds`, `createdAt`, `category` |
| `ShoppingList` | `id`, `partyId`, `title`, `estimatedAmount`, `assignedUserId`, `isBought`, `boughtById`, `actualAmount`, `convertedExpenseId`, `category`, `createdAt` |
| `PaymentStatuses` | `partyId`, `transferId`, `fromUserId`, `toUserId`, `amount`, `isPaid`, `updatedBy`, `updatedAt` |

`legacyPaymentUrl` остаётся только для совместимости со старыми строками и нигде не читается приложением. Новые платёжные ссылки не создаются.

### Возможности

1. Регистрация и вход по телефону/паролю, токен сессии.
2. Создание комнаты с кодом (например, `PUB777`) и присоединение по коду.
3. Состав комнаты — реальные пользователи из `PartyMembers`; банк хранится отдельно для каждой комнаты.
4. Общие расходы: добавление, редактирование и удаление синхронизируются через таблицу.
5. Статусы оплат: подтвердить или отменить перевод может **только должник или получатель** этого перевода. Остальные участники видят статус, но не могут его менять. Проверка выполняется в интерфейсе, в store и на бэкенде.
6. **Мгновенный отклик:** выход из комнаты, отметка оплаты, добавление/редактирование/удаление расхода и название комнаты применяются в интерфейсе сразу. Запись уходит в фоне.
7. **Очередь записи:** действия сериализуются, повторные нажатия схлопываются, несколько операций уходят одним `batch`-запросом. При сетевой ошибке, `429` или `5xx` выполняются повторы с экспоненциальной задержкой. После окончательной ошибки локальное состояние откатывается, показывается тост.
8. **SWR-обновление:** данные комнаты берутся из памяти/AsyncStorage мгновенно, затем фоновая ревалидация. Базовый интервал — 4 секунды, при ошибках он растёт до 60 секунд; в фоне опрос идёт реже, при возврате в приложение принудительно запрашивается свежий снимок. Пока очередь записи не пуста, опрос не перетирает оптимистичные изменения.
9. **Защита от гонок:** локальные правки помечаются ожидающими до подтверждения таблицей, удаления — «надгробиями», поэтому фоновое обновление не воскрешает удалённые позиции.
10. URL Apps Script можно заменить в профиле; пустое поле возвращает встроенный URL.

### Производительность бэкенда

- Схема таблицы проверяется один раз и кэшируется в `CacheService` на 6 часов (ключ версии схемы).
- Чтение комнаты кэшируется на 5 секунд и сбрасывается после каждой записи.
- Используются только нужные колонки листов; поиск строк — через `TextFinder`, без чтения всей таблицы.
- `getPartyDetails` читает участников, пользователей, расходы и статусы по одному разу; банк участника больше не запрашивается отдельно для каждого человека.
- Выход из комнаты обновляет все затронутые строки расходов одним `setValues`. Добавление/удаление расхода идемпотентны, поэтому повтор запроса безопасен.

> ⚠️ После обновления `backend/Code.gs` обязательно сделайте **новое развёртывание**: Deploy → Manage deployments → Edit → Version: New version → Deploy. URL не меняется. Проверка подключения в приложении требует **API версии 2 и поддержки `batch`** и сообщит, если развёртывание старое. Очередь умеет работать и со старым бэкендом (шлёт запросы по одному), но батчи, серверный кэш и оптимизированные чтения появятся только после развёртывания новой версии.

## 📦 Обновления приложения (GitHub Releases)

Встроенный апдейтер больше не использует Google Drive. Он запрашивает последний релиз через GitHub API:

```
https://api.github.com/repos/{owner}/{repo}/releases/latest
```

и сравнивает `tag_name` с `CURRENT_APP_VERSION` (`src/config/version.ts`) по правилам semver (`src/utils/semver.ts`).

### Настройка репозитория

Укажите реальные владельца и название репозитория в `src/config/github.ts`:

```ts
export const GITHUB_OWNER = 'Susich';
export const GITHUB_REPO = 'AntiProjects_2';
```

Либо задайте переменные окружения Expo (они встраиваются при сборке):

```bash
EXPO_PUBLIC_GITHUB_OWNER=Susich
EXPO_PUBLIC_GITHUB_REPO=AntiProjects_2
```

Репозиторий должен быть **публичным**: приложение обращается к GitHub API без токена. Если значения не заданы, экран обновления покажет понятную ошибку конфигурации вместо скачивания устаревшего APK.

### Публикация обновления

1. Поднимите версию в `package.json`, `app.json` (`expo.version` и `android.versionCode`) и `src/config/version.ts`.
2. Соберите APK через EAS (например, профиль `preview`/`production`).
3. Создайте GitHub Release с тегом вида `v1.0.6` (без тега `latest` — GitHub сам считает последним самый новый стабильный релиз).
4. Прикрепите к релизу `.apk`-файл. Приложение берёт первый asset с расширением `.apk`.
5. Текст релиза (`body`) показывается в модальном окне «Что нового».

Кнопка «Обновить» скачивает APK, сохраняет его в кэш приложения и открывает системный установщик Android. Если установленная версия не старше последней, показывается сообщение «У вас установлена последняя версия».
